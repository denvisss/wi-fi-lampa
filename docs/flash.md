# Прошивка и первый запуск

Готовый образ не нужно собирать: скачайте `lampa-full.bin` из
[релизов](https://github.com/denvisss/wi-fi-lampa/releases) и прошейте плату любым
удобным способом. В полном образе уже есть и прошивка, и веб-интерфейс.

## Что понадобится

- ESP8266 (NodeMCU v2/v3 или аналог с 4 МБ flash).
- USB-кабель и, при необходимости, драйвер CH340/CP2102.
- Браузер Chrome или Edge — для веб-прошивальщика.
- Для сборки из исходников — PlatformIO (`pip install platformio`) и Node.js 18+.

## 1. Прошивка готовым файлом

Скачайте `lampa-full.bin` со страницы релизов. Это полный образ на 4 МБ: внутри
прошивка и файловая система с веб-панелью, поэтому одного файла достаточно.

### Веб-прошивальщик — без установки программ

Подойдёт [esptool.spacehuhn.com](https://esptool.spacehuhn.com/) или любой другой
прошивальщик на WebSerial. Нужен Chrome или Edge: Firefox WebSerial не поддерживает.

1. Подключите плату по USB. Если порт не появился — установите драйвер CH340.
2. Откройте [esptool.spacehuhn.com](https://esptool.spacehuhn.com/) и нажмите
   **Connect**, выберите порт `COMx`.
3. Нажмите **Choose file** и выберите `lampa-full.bin`.
4. Адрес оставьте `0x0` — образ уже собран целиком.
5. Нажмите **Program** и дождитесь сообщения об успехе (1–3 минуты). Плата
   перезагрузится сама.

### Espressif Flash Download Tool — Windows

Скачайте [Flash Download Tools](https://www.espressif.com/en/support/download/other-tools)
с сайта Espressif и запустите `flash_download_tool_*.exe`:

1. ChipType — **ESP8266**, WorkMode — **Develop**, LoadMode — **UART**, OK.
2. Галочка в первой строке, файл `lampa-full.bin`, адрес **0x0**.
3. SPI SPEED — **40MHz**, SPI MODE — **DIO**, FLASH SIZE — **32Mbit**.
4. Выберите COM-порт, BAUD — 115200 и больше.
5. **START** → ждите `FINISH`. После прошивки передёрните питание.

### Двумя файлами

Если прошиваете раздельно (например, обновляете только файловую систему):

| Файл | Адрес |
| --- | --- |
| `firmware.bin` | `0x0` |
| `littlefs.bin` | `0x200000` |

### Сборка из исходников

```bash
npm run embed          # копирует web/* в firmware/data и готовит .gz
cd firmware
pio run                # компиляция
pio run -t upload      # прошивка
pio run -t uploadfs    # файловая система с веб-интерфейсом
```

Готовые бинарники: `firmware/.pio/build/lampa/firmware.bin` и `littlefs.bin`.

Если плата не определяется — проверьте драйвер USB-UART и порт в
`pio device list`. Для NodeMCU обычно CH340.

> **Важно:** WS2812B подключена к GPIO2 (D4) — при старте на этой ноге не должно
> быть посторонней подсветки/подтяжек, иначе плата может не загрузиться. Подробнее
> в [wiring.md](wiring.md).

## 2. Первый запуск

1. Включите лампу. При каждом старте она на несколько секунд поднимает открытую
   точку доступа **Lampa-Setup**; если сохранённой сети нет или она недоступна,
   точка остаётся висеть, пока вы её не настроите.
2. Подключитесь к ней телефоном — откроется страница настройки (или зайдите на
   `http://192.168.4.1`).
3. Выберите сеть, введите пароль, нажмите «Подключить». Лампа перезагрузится.
4. Откройте `http://lampa.local` — веб-интерфейс. Если mDNS не работает в вашей
   сети, используйте IP из списка клиентов роутера.

Часы и будильник синхронизируются по NTP. Часовой пояс по умолчанию —
`Europe/Moscow`, меняется в разделе «Часы» веб-панели или приложения: там же
доступны все 465 поясов IANA и ручная установка даты и времени, если интернета нет.

## 3. Обновление по воздуху

Три способа, все сохраняют настройки:

1. **С GitHub** — «Настройки → Прошивка → Проверить» в веб-панели или приложении.
   Лампа сама сходит в релизы `denvisss/wi-fi-lampa`, покажет версию и заметки и по
   кнопке «Обновить» скачает `firmware.bin` и перезагрузится. Прогресс виден в
   интерфейсе в реальном времени.
2. **Из файла** — «Выбрать файл прошивки» там же: подойдёт любой `firmware.bin`
   (не `lampa-full.bin`).
3. **Из консоли** — ArduinoOTA (порт 8266):

```bash
cd firmware
pio run -t upload --upload-protocol espota --upload-port lampa.local
```

Хост `lampa.local` должен разрешаться. Android-приложение обновляется само:
«Настройки → Приложение → Проверить» скачает APK из того же релиза GitHub.

Если после обновления менялся веб-интерфейс — не забудьте `npm run embed` перед
сборкой `uploadfs`.

## 4. Сброс

**Настройки → Сброс → Сбросить до заводских**: удаляются Wi-Fi и все настройки,
лампа снова поднимает точку доступа `Lampa-Setup`.

Сброс без телефона: выключите лампу, зажмите сенсорную кнопку и включите питание,
не отпуская её 3 секунды. Настройки Wi-Fi и сама лампа вернутся к заводским, после
перезапуска появится `Lampa-Setup`.

Если веб-интерфейс недоступен, прошейте файловую систему и настройки заново по USB
(`pio run -t uploadfs`) — точка доступа появится снова.

Настройки лампы (Wi-Fi, яркость, калибровка, будильники, лимит тока) дополнительно
дублируются в EEPROM и переживают `uploadfs`, обновление прошивки и форматирование
LittleFS: при старте без `config.json` лампа восстанавливает их и перезаписывает
файл. Сбрасывают их только «Сброс до заводских» и жест сенсором.

## Если не видно `Lampa-Setup`

Прошивка всегда пишет ход загрузки в Serial на скорости 115200. Подключите плату по
USB и откройте монитор:

```bash
cd firmware
pio device monitor
```

Ожидаемый лог при первом запуске:

```
[lampa] fw 1.3.0, reset reason: Power on
[net] starting setup AP
[net] AP 'Lampa-Setup' up ip=192.168.4.1 mac=...
[lampa] ready: connect to 'Lampa-Setup', open http://192.168.4.1
```

Если сеть уже настроена и доступна:

```
[net] starting setup AP
[net] AP 'Lampa-Setup' up ip=192.168.4.1 mac=...
[net] STA connect to 'Home', timeout 25s
[net] connected ip=192.168.1.42
[net] online, setup AP shuts down shortly
[net] AP stopped, station online
```

| Что в логе | Что делать |
| --- | --- |
| Лога нет совсем | Прошивка не запущена: проверьте порт, повторите `pio run -t upload` |
| `Wi-Fi timeout, setup AP stays up` | Сохранённая сеть недоступна (роутер сменился или пароль другой). AP остаётся — подключитесь и настройте заново, либо сбросьте Wi-Fi удержанием сенсора при включении |
| `softAP failed, retrying`, затем `FAILED` | Сбой радио или питания: проверьте блок питания 5 В и общую землю |
| `AP ... up`, но телефон сеть не видит | Телефон в 5 ГГц-only режиме или далеко от лампы; сеть открытая, 2.4 ГГц |

Точка доступа поднимается до инициализации матрицы, поэтому для первой настройки
ленту можно вообще не подключать. Загрузочная анимация теперь тусклая — чтобы
слабый блок питания не уводил плату в перезагрузку в момент старта.

## Возможные проблемы

| Симптом | Причина и решение |
| --- | --- |
| Плата не прошивается | Нет драйвера CH340/CP2102, занят COM-порт, плохой кабель |
| `Failed to connect` в прошивальщике | Зажмите кнопку FLASH (или BOOT) на плате в момент подключения и отпустите после старта записи |
| Плата не загружается, мигает первый светодиод | На D4 подтяжка/помехи: отключите ленту при прошивке, проверьте резистор 330–470 Ом |
| `lampa.local` не открывается | mDNS блокируется сетью — используйте IP; проверьте, что телефон в той же сети |
| Неверное время | Нет выхода в интернет или неверный часовой пояс; NTP повторяется каждые 6 часов. Без интернета время можно выставить вручную: «Часы → Установка времени» |
| Матрица показывает «кашу» | Неверная ориентация ленты: включите калибровку в настройках (сетка/бегущая точка, змейка/зеркало/переворот/сдвиг) |
| Мигает/выключается на ярких эффектах | Блок питания слабый: нужно 5 В 10–15 А и подвод питания с двух концов матрицы; в настройках уменьшите лимит тока БП (например, до 3000 мА для блока 5 В 3 А) |
